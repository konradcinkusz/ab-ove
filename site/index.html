ab-ovo

A book you work, not a book you read.

ab-ovo is a learning platform being built around Mathematics from Zero for the AI Engineer — 47 programs of programmed-learning frames, in English and Polish, together with the book’s computer exercises. The frames are Stroud’s: each one asks you for something before it tells you anything, and the next frame opens with the answer you should have written. A PDF cannot enforce that, and paper has no way to notice when a reader skims.

Where this stands

Nothing is deployed. There is no running instance of ab-ovo, at any address, for anybody. You cannot read a frame here, and this page is not a way in to one.

What exists is a repository: a web application that builds, an acceptance suite that drives it in a real browser, and one vertical slice of the reader loop that works. This page describes that, and names where each claim on it can be checked.

The anti-goal, before the features

The instrument measures the book, never the reader.

When a frame is answered wrongly by many readers, that is evidence about the frame — its wording, its position, the frame before it — and it goes into revising the book. It is not evidence about the people who answered. There is no leaderboard, no ranking and no per-reader score, and the absence is structural rather than promised: the outcomes table is keyed on a frame, a check, an attempt and a verdict, and carries no identifier and no timestamp, so there is nothing a per-reader view could be built from.

This is stated here, above everything else, because the pressure to misuse a number arrives from somebody who did not read to the end. A claim made in public is one a later feature has to argue with. docs/adr/0009-the-instrument-measures-the-book.md carries the reasoning.

The loop the product is built around

  1. Read a frame. It is short by construction — one idea, sometimes one line.
  2. Commit an answer before you turn over. The commitment is the mechanism; a frame you skimmed teaches nothing, and the book is built on that assumption.
  3. Reveal the next frame, which opens with the answer. Compare, then carry on or go back one.
  4. Where a program has computer exercises, work them in the lab pane. Python runs in your own browser, and your code does not leave the machine.

Two properties that are structural

The answer is absent, not hidden

The reveal is a navigation. The answer to the frame you are on is rendered by the request for the next one and by nothing before it, so a reader who opens the inspector finds it nowhere in the document — and prefetching is off, so it is not on the wire either. That is the difference between a mechanism and a discipline somebody has to keep, and an acceptance test asserts exactly it against the DOM, in both languages and on the route where a frame shares a page with the lab. tests/e2e/specs/frame-view.spec.ts and tests/e2e/specs/frame-and-lab.spec.ts are where it is asserted, and both were watched failing before they were believed.

The exercises run in your own browser, from this origin

The book’s computer exercises are Python, and their checks run client-side under Pyodide — no account, no backend, and no reader-supplied code executed on any server. A check compares strings rather than floats, because two numbers are the same number only if they print the same way; a failed check names the frames to re-read and never the solution, because the whole mechanism of the book is that you commit an answer before you see one.

A Python runtime in a browser is a real download, so it was measured.

One journey through the lab page, first visit and second.
Cost First visit Second visit
Bytes over the wire about 6.6 MB about 2 KB
Until the Check button enables 2.08–2.43 s 1.75–2.02 s

Caching the bytes does not buy back the boot. A second visit transfers essentially nothing and still spends about two seconds, so the wait is instantiating WebAssembly and starting CPython rather than transferring anything. Those figures are one machine’s — headless Chromium on a four-vCPU container, eight runs, 19 September 2026, driving a server over loopback — so the transfer itself was essentially free there, and a reader adds their own link on top of it. The ranges, the file-by-file breakdown and what was deliberately not measured are in docs/adr/0007-exercise-checks-are-python-in-the-browser.md.

What the frame view is reading today

A fixture: four steps, written for this repository and marked as such — the bundle’s own version tag is fixture-0. It is enough to build the schema, the loader and the view against, and it is not the book.

The book’s 47 programs will arrive as a versioned bundle attached to the book’s own release; no such release exists yet. The schema, the loader and the view did not have to wait for it, and did not.

Two licences, and only one of them is here

This repository is MIT. The book’s content is CC BY-NC-SA, and it is not committed here: it is fetched at a pinned revision, file by file, each against its own sha256, and the fetch fails loudly on a mismatch so that a silently edited file cannot pass for a fetched one. web/content/book.lock.json is the pin, and it names the revision, the licence and every digest.

This page fetched nothing. No font, stylesheet, script, icon or image comes from anywhere but this address; the whole document is one file, and there is no JavaScript on it to disable. That is the product’s own rule, kept here because a page advertising it while loading a font from a third party would have falsified it in the first request you made.
